# Муха идёт по маршруту (NeuroMechFly v2 / FlyGym 2.1)

Учебный проект: физическая модель тела дрозофилы (NeuroMechFly v2, библиотека
[FlyGym](https://neuromechfly.org)) проходит по плоской арене маршрут из `route.yaml`.
Результат: видео, траектория в CSV и её график. Муха также умеет идти к тому, что видит,
и убегать от надвигающегося столба; в последнем случае решает модель всего её мозга,
собранная из коннектома (138 639 нейронов, см. [ниже](#мозг-из-коннектома-муха-убегает-от-надвигающегося-столба)).

## Запуск

Нужен [uv](https://docs.astral.sh/uv/): он сам скачает Python 3.12 и поставит зависимости в папку
`.venv` проекта. Подготовка (один раз), из папки проекта:

```powershell
# если uv ещё не установлен; после установки откройте новый терминал
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
uv venv --python 3.12
uv pip install -r requirements.txt
```

На Linux и macOS uv ставится командой `curl -LsSf https://astral.sh/uv/install.sh | sh`, остальное так же.
Если окружение было создано раньше, повторите последнюю строку: для мозга из коннектома добавился `pyarrow`.

Маршрут из примера:

```bash
uv run run_route.py
```

Симуляция маршрута (11.3 с модели) занимает около 2.5 минут: на i7-9700F одна секунда модели
считается примерно 12 секунд.

## Результаты (`./output`)

| Файл | Что внутри |
|---|---|
| `route.mp4` | видео с камеры, которая следует за мухой и смотрит сверху (0.5× скорость, 25 fps, 640×480) |
| `trajectory.csv` | `time_s, x_mm, y_mm, heading_deg, step, action`, каждые 10 мс |
| `trajectory.png` | траектория сверху, цвет = шаг маршрута, стрелки = направление мухи раз в секунду |
| `run.log` | ход симуляции и сводка по шагам: сколько муха прошла и на сколько градусов повернула |

Оси везде одинаковые: x вправо, y вверх. `heading_deg` = 0° значит муха смотрит вдоль +x,
положительный угол = против часовой стрелки. Поворот налево увеличивает угол.

## Как менять маршрут

`route.yaml` — список шагов, выполняются сверху вниз:

```yaml
- {action: forward, duration_s: 3.5, strength: 1.0}
- {action: left,    duration_s: 3.0, strength: 0.1}   # плавный поворот
- {action: right,   duration_s: 0.3, strength: 0.7}   # резкий поворот
- {action: stop,    duration_s: 2.0}                  # strength можно не писать
```

- `forward`: `strength` = амплитуда шага (1.0 = обычная ходьба, около 14 мм/с).
- `left` / `right`: `strength` = резкость поворота. Внешняя сторона шагает с амплитудой 1.0,
  внутренняя с амплитудой `1 − 2·strength`: 0 = прямо, 0.5 = внутренние ноги стоят,
  1.0 = внутренние ноги шагают назад (разворот почти на месте).
- `stop`: обе стороны 0, муха останавливается.

Другой файл маршрута: `uv run run_route.py my_route.yaml`.

Скорость поворота на наших прогонах (примерно, зависит от предыдущего шага):

| strength | скорость поворота |
|---|---|
| 0.1 | ~30°/с, плавная дуга |
| 0.3 | ~90–100°/с |
| 0.7 | ~220°/с |
| 0.9 | ~310°/с, почти на месте |

Для отладки удобно гонять короткий маршрут на 2–3 секунды.

## Живая муха в окне

`run_live.py` показывает муху в окне MuJoCo в реальном времени, а управлять ей можно с клавиатуры.

```powershell
uv run run_live.py          # вы управляете мухой стрелками
uv run run_live.py vision   # муха сама идёт к тёмному столбу, которого видит глазами
uv run run_live.py escape   # в муху можно бросить столб, и её мозг из коннектома решает, как убежать
```

Режим `escape` управляется так же, как `vision`, но муха стоит, пока её не напугать (см. раздел
[о мозге из коннектома](#мозг-из-коннектома-муха-убегает-от-надвигающегося-столба)).

| Клавиша / мышь | Обычный режим | Режим `vision` |
|---|---|---|
| ↑ | идти | столб от камеры |
| ↓ | стоп | столб к камере |
| ← / → | поворот; повторное нажатие делает его круче (0.3 → 0.5 → … → 1.0) | столб влево / вправо по экрану |
| Ctrl + правая кнопка, тянуть | толкнуть выделенную муху | таскать столб по полу |

В режиме `vision` одно нажатие стрелки сдвигает столб на 3 мм. Стрелки работают относительно
камеры, так что если повернуть вид мышью, «вверх» останется «от вас». Муху ведёт тот же «мозг»,
что и в `run_vision.py` (см. ниже). В **правом нижнем углу** окна показано, что видит муха:
оба глаза, каждый из 721 омматидия. В левом верхнем углу видно, сколько «тёмного» видит каждый глаз,
что решил мозг и сколько осталось до столба. Проверено: муха доходит до стартового положения столба
за ~1.7 с, а после сдвига столба сама поворачивает и снова останавливается в 3–4 мм от его центра.

Столб можно **таскать мышью**: зажмите Ctrl и тяните правой кнопкой. Столб выделен с самого старта.
Если вы двойным кликом выделили что-то другое, например муху, сначала дважды кликните по столбу.
Штатно MuJoCo таскает объект в вертикальной плоскости и поднял бы столб в воздух, поэтому
`run_live.py` переводит движение мыши вверх/вниз в «от вас / к вам» по полу. Это проверено вызовом
тех же функций MuJoCo, что вызывает окно при перетаскивании (`mjv_initPerturb` / `mjv_movePerturb`).
Настоящую мышь автоматически проверить не удалось: Windows не даёт фоновому скрипту
вывести окно на передний план.

Защита от сбоев физики:
- **Вращать тела мышью (Ctrl + левая кнопка) нельзя.** Такое вращение ломает физику этой крошечной
  модели: в тестах поворот мухи на 30–180° давал NaN даже с точными настройками `run_route.py`.
- **Если физика всё-таки сорвётся**, MuJoCo сбросит модель в странную позу. Тогда `run_live.py` сам
  поставит муху заново и напишет об этом в консоли. Проверено на двух нарочно устроенных сбоях подряд.

| Мышь | Действие |
|---|---|
| левая кнопка + тянуть | вращать камеру (она следует за мухой) |
| правая кнопка + тянуть / колесо | сдвинуть / приблизить камеру |
| двойной клик по мухе, затем Ctrl + правая кнопка | толкнуть муху |

Остальные клавиши встроены в сам MuJoCo. Например, буквы переключают отображение
(каркас, коллизионные формы), Tab / Shift+Tab открывают панели настроек.
Если картинка стала странной, просто перезапустите окно.

Чтобы успевать за реальным временем, физика считается грубее, чем в `run_route.py`.
Настройки задаются константами в начале `run_live.py`:

| | `run_route.py` | `run_live.py` |
|---|---|---|
| шаг физики | 0.1 мс | 0.25 мс |
| частота контроллера | 10 000 Гц | 500 Гц |
| noslip-итерации MuJoCo | 5 | 2 |
| скорость на i7-9700F | ~12× медленнее реального времени | **~0.93× реального времени** при ходьбе, ~0.85× стоя; в режиме `vision` ~0.8× |

Походка при этом почти та же: за 1 с ходьбы 12.9 мм против 13.1 мм, поворот на 0.3 за 1 с
+105° против +111°. Грубее нельзя: при шаге физики 0.5 мс муха начинает подпрыгивать,
а при контроллере 250 Гц повороты слабеют вдвое. Текущая скорость показана в левом верхнем углу
окна: если она меньше 1.0, муха движется чуть замедленно. Быстрее реального времени симуляция
не идёт, лишнее время она ждёт.

## Муха идёт к тому, что видит (зрение)

```bash
uv run run_vision.py          # столб по умолчанию: (-10, 25) мм, сзади-слева
uv run run_vision.py 20 -15   # свой столб: x y в мм
```

Муха стартует в точке (0, 0) носом вдоль +x, на арене стоит тёмный столб (радиус 1.5 мм, высота 10 мм).
Мухи и в жизни поворачивают к тёмным вертикальным полосам (stripe fixation). Результаты:
- `output/vision.mp4`: сверху арена, снизу то, что видит муха (левый глаз | правый глаз);
- `output/vision.png`: путь мухи и столб;
- `output/vision.log`: что видят глаза и что решает «мозг» каждые 0.5 с.

Как это работает:

1. **Глаза.** `fly.add_vision()` ставит в глаза две камеры с обзором 157° каждая.
   20 раз в секунду FlyGym рендерит их и усредняет картинку по **721 омматидию на глаз**
   (`sim.get_ommatidia_readouts`). Одно чтение обоих глаз занимает ~5 мс.
2. **Что считать объектом.** Выше горизонта фон — светлое небо (яркость 1.0), ниже тёмный пол.
   Поэтому «мозг» смотрит только на омматидии выше горизонта (строка картинки глаза < 220):
   тёмное там — это объект. В пустой арене сумма «темноты» там ≈ 0.01.
3. **«Мозг»** (функция `brain`):
   - почти ничего не видно (сумма темноты < 0.3, например столб в слепой зоне сзади) —
     поворот на месте, чтобы осмотреться;
   - темноты очень много (> 100, столб заслонил обзор, ~5 мм до центра) — стоп, пришли;
   - иначе поворот в сторону глаза, который видит тёмное пятно, тем круче, чем дальше пятно
     от направления «прямо». Столб прямо впереди оба глаза видят одинаково, и сигнал поворота равен 0.
4. Решение превращается в тот же сигнал `[левая, правая]`, что и в маршруте, и уходит контроллеру ходьбы.

Проверено:

| Столб | Где относительно мухи | Дошла за | Остановилась от центра столба |
|---|---|---|---|
| (−10, 25) | сзади-слева | 2.1 с | 3.5 мм |
| (20, −15) | спереди-справа | 1.7 с | 4.0 мм |
| (−25, −5) | в слепой зоне сзади | 2.6 с* (0.3 с осматривалась) | 3.5 мм |
| (30, 0) | прямо впереди | 1.9 с* | 4.3 мм |

\* прогоны с быстрыми настройками физики из живого режима. Ни в одном случае муха не виляла:
смен направления поворота 0.

Она отключена, но сохранена в git-ветке `odor`: `git switch odor`.

## Мозг из коннектома: муха убегает от надвигающегося столба

Здесь решение принимает не функция, написанная руками, а модель всего мозга мухи,
собранная из коннектома. Столб летит в стоящую муху; глаза видят, как он растёт; мозг
отвечает через нисходящие нейроны, и муха разворачивается и убегает.

```bash
uv run run_escape.py                 # столб летит слева-спереди (60°)
uv run run_escape.py -60             # справа-спереди; 0 = спереди, 180 = сзади
uv run run_escape.py 60 --shuffled   # контроль: та же муха, случайная проводка
uv run run_escape.py 60 --mcns       # мозг самца вместо FlyWire (см. ниже)
uv run brain.py                      # проверка модели по опубликованным результатам
```

В живом окне: `uv run run_live.py escape`. Муха стоит, а вы бросаете в неё столб стрелками или
мышью (Ctrl + правая кнопка), как в режиме `vision`. В левом верхнем углу числа: вход в
нейроны-детекторы, гигантские волокна, DNa, MDN и итоговый сигнал ногам. В правом верхнем углу
**картинка мозга**: какие его нейроны сейчас стреляют (см. ниже). `uv run run_live.py escape mcns`
делает то же на мозге самца.

Первый запуск скачивает коннектом (около 130 МБ, с GitHub авторов модели и FlyWire) и превращает его
в `data/connectome_783.npz` (115 МБ). Это занимает около минуты, дальше загрузка идёт несколько секунд.
Мозг самца при первом запуске скачивает около 1.1 ГБ и превращается в `data/connectome_mcns.npz`
(232 МБ), тоже примерно за минуту; скачанные файлы после этого удаляются. В git папка `data/` не попадает.
Если коннектом был собран до того, как в нём стали храниться положения нейронов, первый запуск
докачает только таблицу нейронов (31 МБ у FlyWire, 14 МБ у самца) и допишет положения, связи не трогает.

Результаты `run_escape.py` в `./output`, имена по направлению (`escape_60.*`, `escape_-60.*`, …):
- `escape_60.mp4`: сверху арена, под ней то, что видит муха, внизу картинка мозга;
- `escape_60.png`: слева пути мухи и столба, справа вход в мозг и ответ нисходящих нейронов;
- `escape_60.log`: то же числами каждые 50 мс.

### Картинка мозга

Каждый нейрон — точка там, где лежит его тело (так их рисует и [Swat](https://github.com/hrook1/Swat)).
Вид спереди, левая сторона мухи слева. Из самих точек получается силуэт: большой мозг, по бокам
зрительные доли, у самца внизу нервная цепочка (VNC). Нейрон, который выстрелил, вспыхивает и гаснет
примерно за 0.3 с. Синие точки — вход (LC4, LPLC2, LC16), красные квадраты — нейроны, которые
мы читаем (GF, DNa, MDN, у самца ещё TTMn): яркие, когда стреляют, тусклые в покое. Остальные
вспышки жёлтые. Когда столб летит слева, видно, как загораются синие детекторы левого глаза, по
мозгу расходятся тысячи жёлтых вспышек и загораются красные квадраты.

Положение тела известно у 138 625 нейронов FlyWire из 138 639 (у остальных оно не записано) и у
141 000 нейронов самца из 165 122: у сенсорных нейронов тело лежит вне нервной системы, в
коннектоме его нет. Такие нейроны считаются, но не рисуются. Связей на картинке нет: их 15–25 млн,
вышла бы сплошная каша. Картинка рисуется за 2–3 мс и скорость окна не меняет.

### Что это за мозг

Модель Shiu et al. (2024, Nature) «leaky integrate-and-fire», построенная на коннектоме FlyWire v783:
**138 639 нейронов и 15.1 млн связей (54.5 млн синапсов)**. Каждый нейрон — простая «копилка» напряжения
с утечкой: при −45 мВ он даёт спайк и сбрасывается. Каждый синапс возбуждает или тормозит соседа,
смотря по нейромедиатору. Вес связи пропорционален числу синапсов. Все константы взяты из
[`model.py`](https://github.com/philshiu/Drosophila_brain_model) авторов.

Авторы считают модель в Brian2. На этой машине Brian2 тратит около 40 с на секунду модели
(режим numpy, вместе с построением сети), поэтому в `brain.py` те же уравнения переписаны
на numba (он уже стоит вместе с FlyGym).
Получается около 0.7 с на секунду модели на 8 ядрах, пока мозг активен. Когда входа нет
и все нейроны затихли, шаги не считаются вовсе, а оставшиеся потенциалы затухают по точной формуле.

**Проверено** (`python brain.py`): повторён пример авторов, для которого они выложили результат Brian2.
21 сахарный рецептор правой стороны стимулировали 200 Гц, 30 прогонов по 1 с, коннектом v630.

| | Brian2 (авторы) | `brain.py` |
|---|---|---|
| нейронов со спайками | 448 | 449 |
| корреляция частот всех нейронов | | 0.9998 |
| MN9 (мотонейрон хоботка: муха начинает есть) | 93.3 Гц | 95.0 Гц |

При проверке всплыла деталь, которой нет в описании модели. В Brian2 вход, пришедший к нейрону
во время его рефрактерного периода (2.2 мс после спайка), **теряется**. Если такой вход копить,
частоты нейронов ниже сахарных рецепторов выходят на треть выше (MN9 121 Гц вместо 93).
Проверено на сети из 22 нейронов (21 → 1): Brian2 даёт 159 Гц, `brain.py` 160 Гц.

### Как устроена петля

Каждые 50 мс, в такт чтению глаз:

1. **Глаза.** Как в `run_vision.py`, берётся «темнота» омматидиев выше горизонта. Для каждого глаза
   считается, насколько быстро растёт тёмное пятно за последние 0.1 с (омматидиев в секунду).
   Окно в 0.1 с — это один шаг ноги, поэтому качание головы при ходьбе в нём гасится.
2. **Вход в мозг.** Рост быстрее 50 омматидиев/с превращается в пуассоновский вход, как оптогенетика
   в статье: 0.5 Гц на каждый омматидий/с сверх порога, не больше 150 Гц. Вход идёт в нейроны-детекторы
   надвигающегося объекта того же глаза: LC4, LPLC2 и LC16, 239 слева и 226 справа.
3. **Мозг** считает 50 мс, все 138 639 нейронов.
4. **Выход.** Считываются спайки нисходящих нейронов (они идут из мозга к ногам):
   - гигантские волокна DNp01 (нейроны побега) → насколько быстро бежать;
   - DNa01 + DNa02, разность справа минус слева → куда поворачивать;
   - MDN («moonwalker») → идти назад.
5. **Ноги.** Из этого собирается тот же сигнал `[левая, правая]` для `HybridTurningController`.
   Бег держится ещё около 0.6 с после того, как волокна замолчали, поворот и ход назад около 0.2 с.
   Поэтому муха сначала поворачивается, а потом бежит.

| Решает коннектом | Выбрано руками |
|---|---|
| сработают ли нейроны побега; какие DNa загорятся, слева или справа; включится ли ход назад | как рост пятна превращается в частоту входа; какие нейроны считать входом и выходом; как частоты превращаются в сигнал ногам (константы в начале `run_escape.py`) |

### Что получилось

Столб (радиус 1.5 мм) летит со скоростью 60 мм/с с 30 мм и останавливается в 6 мм от места, где
стояла муха. Физика точная, как в `run_route.py`, 3 с модели.

| Откуда столб | Что ответил мозг | Что сделала муха |
|---|---|---|
| слева-спереди, 60° | гигантские волокна; DNa справа | повернула **направо** на 51°, отошла на 4.8 мм |
| справа-спереди, −60° | гигантские волокна; DNa слева; немного MDN | повернула **налево** на 62°, отошла на 3.9 мм |
| спереди, 0° | волокна, затем DNa слева и MDN | около 3 мм вперёд, потом налево на 93°, отошла на 4.5 мм |
| сзади, 180° | ничего: столб в слепой зоне глаз | стоит |
| слева-спереди, **перемешанная проводка** | ничего | стоит |

«Отошла» — насколько дальше от точки остановки столба муха оказалась в конце. Прогон занимает
около 45 с, почти всё время уходит на физику: мозг работает только полсекунды, пока летит столб.
Результат повторяется до градуса от запуска к запуску и совпадал с Linux, пока проект запускался
в Docker. `uv run brain.py` считается 17 с.
Во всех случаях муха поворачивает **от** угрозы. В коде нигде не написано «повернись от неё»:
это следует из того, какие DNa возбуждаются через проводку. С угрозой спереди направление решает
случай. На старте ходьбы муха уходит влево примерно на 10° (см. ограничения), столб оказывается
в правом глазу, и мозг разворачивает её влево.

**Контроль** (`--shuffled`). Каждый нейрон сохраняет свои синапсы, их число и знак, но они ведут
к случайным нейронам. Вход тот же (до 150 Гц), а гигантские волокна, DNa и MDN не дают
ни одного спайка.
Поведение держится именно на проводке, а не на количестве нейронов и синапсов.

В живом окне проверено скриптом, который «нажимал» стрелки так же, как обработчик клавиатуры.
Столб бросили слева, волокна сработали, муха развернулась направо на 86° и отбежала
(расстояние до столба выросло с 2.6 до 8.7 мм). В покое окно идёт со скоростью около 0.78×
реального времени, во время побега около секунды проседает до 0.5×.

### Второй коннектом: мозг самца (male CNS)

`--mcns` берёт коннектом [male CNS v1.0](https://male-cns.janelia.org/) (Janelia, Berg et al. 2025,
лицензия CC-BY). Это другая муха, и не только мозг: вместе с ним брюшная нервная цепочка (VNC),
где сидят нейроны ног и крыльев. **165 122 вычитанных нейрона, 25.6 млн связей, 124 млн синапсов.**
Все нужные нам нейроны там есть под теми же именами: LC4, LPLC2, LC16, DNp01, DNa01, DNa02, MDN.
Модель та же, код тот же. Отличаются три вещи:

- **Знак синапса.** Shiu et al. считают тормозящими ГАМК и глутамат, остальное возбуждающим
  (это правило восстановлено по их данным). В FlyWire нет гистамина, а в male CNS им пользуются
  около 6 000 нейронов. У мух гистамин открывает хлорные каналы, поэтому он тоже тормозящий.
  Если итоговый нейромедиатор нейрона «неясен» (3 400 нейронов), берётся его собственное предсказание.
- **Вес синапса.** На одних и тех же нейронах male CNS находит в **1.8 раза больше синапсов**,
  чем FlyWire. Это медиана по 4 669 типам, которые есть в обоих коннектомах, и для входов (1.78),
  и для выходов (1.81). Раз разница одна по всему мозгу, дело скорее в том, как искали синапсы,
  а не в самих мухах. Вес 0.275 мВ подбирали под FlyWire, поэтому синапс male CNS весит 0.275 / 1.8.
  Если этого не сделать, мозг перевозбуждён: 10–20 тысяч нейронов спайкают при любом входе, от 20
  до 150 Гц, и сторона поворота теряется.
- **Выход «прыжок».** В VNC есть TTMn, мотонейрон мышцы прыжка, куда гигантское волокно передаёт
  команду взлететь. Он записывается в лог и на график (пунктир). Ноги он не двигает: прыгать наша
  модель не умеет.

Тот же опыт на мозге самца:

| Откуда столб | FlyWire (самка, мозг) | male CNS (самец, мозг и VNC) |
|---|---|---|
| слева-спереди, 60° | направо на 51°, отошла на 4.8 мм | направо на 29°, отошла на 5.3 мм |
| справа-спереди, −60° | налево на 62°, отошла на 3.9 мм | налево на 85°, отошла на 5.4 мм |
| спереди, 0° | налево на 93°, отошла на 4.5 мм | налево на 60°, отошла на 2.5 мм |
| сзади, 180° | стоит | стоит |
| 60°, перемешанная проводка | стоит | стоит |

**Повторилось главное: муха у другой особи поворачивает от угрозы**, потому что DNa загораются
на стороне, противоположной угрозе. С перемешанной проводкой молчат все выходы, включая TTMn.
Гигантские волокна у самца срабатывают раньше и сильнее (при 20 Гц входа около 100 Гц против 40),
поэтому муха начинает бежать до того, как повернулась, и поворот выходит меньше.
**TTMn срабатывает во всех трёх случаях** (40–100 Гц), пока летит столб: в модели команда
«прыгай» проходит от глаз через гигантское волокно до мотонейрона в VNC.

Особенность мозга самца: после испуга в нём остаётся **самоподдерживающаяся петля** примерно из
50 нейронов, нисходящих DNg33 и восходящих нейронов VNC (AN09A005, AN27X013, IN09A005). Они
возбуждают друг друга по кругу, мозг → VNC → мозг, со 100–160 Гц. В модели Shiu нет утомления нейронов,
поэтому погасить петлю нечему. В FlyWire её быть не может: там нет VNC. Наши выходы в неё не входят,
поэтому на поведение она не влияет, но мозг больше не молчит и считается постоянно. Живое окно
после первого испуга идёт около 0.45× реального времени вместо 0.78×.

Прогон `run_escape.py --mcns` занимает около 50 с, чуть дольше, чем на FlyWire.
Проверено и живое окно: столб бросили слева,
муха развернулась направо на 47° и отошла с 2.5 до 6.5 мм.

### Честно о том, что это значит

- LC4 и LPLC2 → гигантское волокно — известный прямой путь, так что его срабатывание ожидаемо.
  Интереснее то, что модель сама выбирает сторону поворота (DNa) и ход назад (MDN).
- То же поведение можно написать правилом в две строки: «повернись от глаза, в котором растёт пятно».
  Похожий проект [FLY-lab](https://github.com/Recluse/FLY-lab) сравнивал коннектом с таким правилом
  и разницы не нашёл. Здесь ценность в другом: правило никто не писал, оно получилось из проводки,
  перемешанная проводка его не даёт, а на коннектоме другой мухи (male CNS) оно повторяется.
- Настоящая муха от угрозы прыгает и улетает: гигантское волокно запускает прыжок. Наша модель умеет
  только ходить, поэтому волокно здесь означает «беги».
- Правая и левая половины мозга отвечают по-разному. Угроза справа включает MDN (ход назад)
  заметно сильнее, чем слева; так устроен коннектом.
- Глаза подключены к мозгу не через сетчатку, а сразу к нейронам-детекторам. Путь от фоторецепторов
  в этой модели не работает. Если стимулировать все фоторецепторы одного глаза (R1–6, R7, R8, 20 Гц),
  ни один спайк не доходит до нисходящих нейронов. Поэтому «рост пятна» считается в Python
  и подаётся прямо в LC4/LPLC2/LC16.
- Датчик роста пятна обманывается объектом, который въезжает в поле зрения сбоку, а не приближается.
  Например, если быстро тащить столб вокруг мухи, она может испугаться.
- Разрешение по времени грубое: 1 спайк за 50 мс — это 20 Гц, поэтому частоты в логе кратны 20.

Модель: Shiu P.K. et al. *A Drosophila computational brain model reveals sensorimotor processing*,
Nature (2024). Коннектом FlyWire: Dorkenwald S. et al., Nature (2024). Типы нейронов:
Schlegel P. et al., Nature (2024). Мозг самца: Berg S. et al., *Sexual dimorphism in the complete
connectome of the Drosophila male central nervous system*, bioRxiv (2025). При публикации
результатов цитируйте их.

## Как это устроено

`run_route.py`, по шагам:

1. `make_locomotion_fly()` + `FlatGroundWorld` + `Simulation`: муха на плоской арене.
2. `fly.add_tracking_camera(mode="track")`: камера над мухой. Её ориентация фиксирована в мире,
   поэтому на видео поворачивается муха, а не арена.
3. Каждый шаг маршрута превращается в двумерный сигнал `[левая, правая]` (функция
   `descending_signal`). Этот сигнал получает `HybridTurningController`: он задаёт
   амплитуду и направление CPG-осцилляторов своей стороны тела. Контроллер
   возвращает углы суставов и включение адгезии для каждого шага физики (0.1 мс).
4. Кадры рендерятся в память и в конце сохраняются в MP4.

## Версии и окружение

- Python 3.12 (uv ставит его сам), flygym **2.1.0**, mujoco **3.9.0**. Все зависимости
  зафиксированы в `requirements.txt` (полный `pip freeze`); `win32-setctime` ставится только на Windows.
- Для мозга из коннектома добавлен только `pyarrow` (читает коннектом один раз, при конвертации).
  Сам мозг считается на numba, который ставится вместе с FlyGym. Brian2 не нужен.
  Данные закреплены по коммитам: модель `philshiu/Drosophila_brain_model@91bdd1e`,
  типы нейронов `flyconnectome/flywire_annotations@8587524`, мозг самца — файлы male CNS v1.0
  (версия записана в их именах) из `storage.googleapis.com/flyem-male-cns`.
- **dm_control не нужен**: FlyGym 2.x собирает модель через `MjSpec` самого MuJoCo,
  зависимости от dm_control больше нет, поэтому версию для него фиксировать не пришлось.
- Раньше прогоны шли в Docker (Linux, программный рендер Mesa). От него отказались: всё то же
  работает прямо в Windows, мозг там считается в 6 раз быстрее, а одно окружение проще, чем два.
  На Linux без экрана видео рендерятся через EGL: поставьте `libegl1 libgl1-mesa-dri` и запускайте
  с `MUJOCO_GL=egl PYOPENGL_PLATFORM=egl` (так был настроен Docker-образ; без Docker на Linux
  это не проверялось).

### Где документация расходится с реальностью

- FlyGym 2.x требует Python ≥ 3.12, так что из диапазона 3.9–3.12 подходит только 3.12.
- `HybridTurningController` больше не входит в ядро `flygym`. Он лежит в
  `flygym_demo.complex_terrain` (ставится тем же `pip install flygym`). Теперь это не
  gym-окружение, как в 1.x: `controller.step(signal, obs)` только возвращает команды,
  а применять их к симуляции и шагать физику нужно самому.
- **Обоняния в релизе FlyGym 2.1.0 нет.** `docs/index.md` пишет, что запах на антеннах смоделирован,
  но в коде 2.1.0 (PyPI и ветка `main`) нет ни источников запаха, ни сенсоров: в 1.x это был `OdorArena`.
  Перенос в 2.x начат в ветке [`olfaction`](https://github.com/NeLy-EPFL/flygym/tree/olfaction)
  (май 2026). Но pull request по ней нет, в ветку следующей версии `dev-v2.1.1` она не попала,
  а написана она на API dm_control, от которого 2.1.0 отказался. Наш самодельный вариант запаха
  (закон обратных квадратов и сенсоры на антеннах) пока отключён и лежит в ветке `odor`.
- **Картинка «глазами мухи»** из `retina.hex_pxls_to_human_readable` строится ~13 мс на оба глаза.
  Это втрое дольше, чем само зрение. В `run_vision.py` та же картинка (совпадает до пикселя)
  получается одной выборкой numpy по карте омматидиев.
- Если отрендерить кадр до первого шага физики, получится полностью белое изображение.
  Поэтому сначала вызывается `sim.warmup()`.

## Известные ограничения

- Ходьба «прямо» не идеально прямая: на первых шагах курс уходит примерно на 10° влево,
  и каждый шаг ноги курс колеблется на ±5°. Поэтому сводка в `run.log` усредняет курс
  по последним 0.1 с шага.
- Инерция: амплитуда CPG меняется плавно (около 0.3–0.5 с). Часть поворота досчитывается
  уже в следующем шаге. После `stop` муха ещё проходит около 1 мм и доворачивает на 20–30°.
- Скорость поворота зависит от `strength` нелинейно, её надо подбирать по `run.log`.
- `run_route.py` медленный: около 12× медленнее реального времени, только CPU. GPU-бэкенд warp
  не используется: он ускоряет тысячи мух параллельно, а не одну. Для живого просмотра есть
  `run_live.py`, но его физика чуть грубее, поэтому он не повторит видео из `run_route.py` точь-в-точь.
- Все кадры хранятся в памяти до конца прогона: около 45 МБ на секунду модели.
  Минутный маршрут потребует около 2.7 ГБ RAM.
- Только плоская арена. Столб — «призрак»: муха его видит, но не может в него врезаться
  (у него нет столкновений), поэтому «мозг» останавливает её заранее.
- Зрительный «мозг» работает только на фоне неба. Тёмный объект ниже горизонта (на тёмном полу)
  он не заметит, а два тёмных объекта сразу воспримет как одно пятно (судя по устройству
  «мозга», пойдёт между ними; это не проверялось).
  Движение он не анализирует, в отличие от настоящих мух.
- Первое чтение глаз компилирует код сетчатки (numba) около 7 с. `run_live.py vision` делает это
  до открытия окна, поэтому окно появляется с задержкой.
- В `vision.mp4` муха мелкая: камера висит высоко, чтобы в кадр попали и старт, и столб.
